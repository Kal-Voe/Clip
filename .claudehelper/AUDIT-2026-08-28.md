Six parallel auditors: visual/rendering, usability, features, stability, performance, plus an external audit of [asyar](https://github.com/Xoshbin/asyar) for the crisp-rendering/transparency question. Audit only — nothing changed.

## The asyar / Raycast question, answered

**Why asyar looks crisper:** it's a Tauri 2 + Svelte 5 app rendered in the OS webview (WKWebView on macOS, WebView2/Chromium on Windows). Browser text stacks (CoreText / DirectWrite+Skia) snap glyphs to device pixels at the devicePixelRatio. WPF's default `TextFormattingMode="Ideal"` places glyphs at *fractional* pixel positions — the classic "WPF looks blurry" cause — and Clip forces `Ideal`+`Grayscale` at the window level (MainWindow.xaml:16-18, repeated at 265-267 and in code-built TextBoxes). The `SetClearTypeHint` call at MainWindow.xaml.cs:865 is a no-op under Grayscale, which suggests a sharpening attempt was already made in the wrong place. There's no magic in the webview — WPF's defaults just actively degrade small text, and `Display` mode largely closes the gap.

**How asyar does transparency:** the `window-vibrancy` 0.6 Rust crate. macOS: `apply_vibrancy` with `NSVisualEffectMaterial::HudWindow` (chosen because it's the only material uniformly translucent in both light and dark) + native CALayer 20px corner radius (asyar-launcher/src-tauri/src/platform/macos/window.rs). Windows: `apply_acrylic(...)` (undocumented `SetWindowCompositionAttribute` path) with `apply_mica` as fallback (src/lib.rs). The glass look = native blur layer + semi-transparent CSS backgrounds on top.

**How Raycast does it:** native AppKit — borderless non-activating NSPanel backed by `NSVisualEffectView` (`blendingMode = .behindWindow`, HUD material). Same OS compositor mechanism as asyar/Alfred/Spotlight; the WindowServer does the blur GPU-side for free.

**The right path for Clip (Windows 11):**
- **Option A — recommended:** `DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE=38, DWMSBT_TRANSIENTWINDOW=3)` (acrylic; `2` = mica) on the existing normal window. Plus: `DwmExtendFrameIntoClientArea` with -1 margins, `HwndSource.CompositionTarget.BackgroundColor = Transparent`, window `Background = Transparent`, and alpha (~0xCC) on the theme's Bg/Surface brushes — `ApplyTheme` (MainWindow.xaml.cs:8456-8477) already centralizes every brush, so it's a per-brush alpha tweak + settings toggle. Gate on build ≥ 22621; opaque fallback on Win10. Documented, GPU-side, no drag lag; DWM draws corners + shadow.
- **Option B:** `SetWindowCompositionAttribute` acrylic (what asyar's `apply_acrylic` actually calls) — undocumented, drag-lag on Win10 1903+; only worth it if Win10 support matters.
- **Option C — never:** `AllowsTransparency=True`. Layered window = DWM backdrops don't render, ClearType hard-disabled, extra readback path, no DWM corners/shadow. It's the anti-pattern that causes exactly the blur being audited.

Bonus finding: the Shell border's `CornerRadius="14"` (MainWindow.xaml:261) never actually shows today — the window's own opaque background paints to the edge, so you see DWM's ~8px system radius. The backdrop route makes the 14px radius the real silhouette.

Text-on-glass caveat: ClearType can't do subpixel over a truly transparent background; keep text on semi-opaque panels (e.g. `#CC1E1E1E`) over the blur, or accept greyscale — at `Display`-mode pixel snapping greyscale still looks clean.

## Visual polish & rendering

1. **`Ideal`+`Grayscale` text** (high/small) — see above. Fix at MainWindow.xaml:16; also at 265-267 and MainWindow.xaml.cs:5794, 14026, 14043.
2. **No PMv2 DPI awareness** (high/small) — no app.manifest anywhere; WPF on .NET 8 defaults to System-DPI-aware, so secondary monitors at different scale get whole-window bitmap stretch. Add manifest with `<dpiAwareness>PerMonitorV2</dpiAwareness>`; verify the manual DPI math at MainWindow.xaml.cs:6815-6820 and 7725 afterward.
3. **Selection border jiggle** (med/small) — selected rows get BorderThickness 1, unselected 0 (MainWindow.xaml.cs:3683, 4103, 4111), so rows shift 1-2px as you navigate. Constant thickness 1, swap BorderBrush only.
4. **Acrylic backdrop viable** (med/medium) — see Option A above; test interaction with DWM cloaking show/hide (MainWindow.xaml.cs:2063-2081).
5. **Inter / JetBrains Mono named but never shipped** (med/small) — font stacks reference them (MainWindow.xaml:120, 132, 215, 253, 399) but no fonts are packaged; users get Segoe UI Variable / Cascadia fallbacks with different metrics than you test against. Bundle (Inter is SIL OFL) as `./Fonts/#Inter` or design against the fallback.
6. **Search icon is a text glyph "⌕"** (low/small) — MainWindow.xaml:296; every other icon is DPI-rasterized. Reuse the DropdownIcon machinery (MainWindow.xaml.cs:11446).

Auditor's overall note: Clip's rendering hygiene (layout rounding, HighQuality scaling, DecodePixelWidth, DPI-aware icons, pixel-matched scrollbars) is better than most WPF apps — the gap is the three items above.

## Usability & UX

1. **No keyboard list navigation** (high/medium) — no Up/Down/PageUp/Home/End anywhere (OnWindowKeyDown, MainWindow.xaml.cs:9005-9100); focus pinned to SearchBox; rows only have mouse handlers. Core launcher loop "type → arrow → Enter" doesn't exist.
2. **Selection detaches from search** (high/small) — search renders with `selectFirst:false` (898-902); stale `_selected` keeps the old preview and Enter pastes it. Fix: after search render, if `_selected` not visible, select first visible.
3. **Esc dead** (high/small) — `TryKey` Enum.TryParse has no "Esc" alias (574-583); live settings.json confirms. Add aliases ("Esc", "Del"); help window still advertises Esc.
4. **Ctrl+K action menu is mouse-only and opens at the mouse cursor** (med/medium) — rows have only mouse handlers (3956-3991); keyboard-open falls back to `PlacementMode.MousePoint` (3999). Add arrow/Enter/Escape handling and place against the selected row.
5. **Footer hints hardcoded and incomplete** (med/small) — MainWindow.xaml:456-473 ignores rebinding; Ctrl+K and Ctrl+Q appear nowhere in the UI.
6. **Alt+V registration failure is silent** (med/small) — retry timer permanently stops (2244-2248), only a debug log. Toast/tray-notify + surface in Settings.
7. **Ctrl+C gives zero feedback** (med/small) — CopySelected (4831-4837); failure paths toast, success doesn't.
8. **Delete is instant, no undo, and the Del key likely never reaches the handler** (med/medium) — DeleteItem (6679-6691); TextBox eats Delete before the window handler (9072-9079). Verify, route via PreviewKeyDown, add one-item undo toast.
9. **No empty states** (low/small) — no-results leaves a blank list with the stale preview still showing; first run gives no hint.

## Functionality & features

1. **Honor password-manager exclusion formats** (high/small) — check the three registered formats in both capture paths (MainWindow.xaml.cs:~2415, Clip.Watcher/Program.cs:~1856); ~10 lines per path. Highest value-per-line in the audit.
2. **Multi-word search** (high/small) — token-AND matching in `MatchesQuery` (ClipboardHistoryStore.cs:512-517); fast path can fall back to object path for multi-token queries.
3. **Pause/resume capture** (med/small) — no toggle exists anywhere; standard in Ditto/ClipboardFusion/Win+V. Bool check at top of both capture paths + tray menu item.
4. **Digit quick-paste Ctrl/Alt+1..9** (med/small) — one branch in OnWindowKeyDown indexing the rendered list; optional numeric badges.
5. **Text transforms + Copy-OCR-text actions** (med/medium) — action menu has zero content transforms; `OcrText` is already stored (ClipboardHistoryItem.cs:62) but only surfaced via search — "Copy Text from Image" alone is worth it. Submenu infra already exists (MenuAction.Submenu, 3878).
6. **Paste-and-stay (Shift+Enter)** (med/medium) — PasteSelected always conceals (4877); a modifier variant that pastes and keeps the palette covers the fill-a-form case without building paste stacks.
7. **"New Snippet" action** (med/small) — pin+rename+edit already form 80% of snippets, but every item must originate from a copy; a footer/tray entry opening the existing EditText modal on a blank pinned item closes the loop.
8. **Export/backup of Clip's own history** (low/small) — store is portable JSON+assets and folder relocation already exists (7879); a zip/restore button is nearly free.

## Stability & correctness

1. **Corrupted history.json permanently kills capture, silently** (high/small) — GetItems deserializes with no try/catch (ClipboardHistoryStore.cs:104-105); palette keeps rendering from the summary index so it looks fine while every capture fails. Quarantine-and-rebuild (sidecars exist per item) + one toast.
2. **Non-atomic saves are the corruption source** (high/small) — SaveCore uses direct WriteAllBytes (1197-1198); the safe temp-file+Move pattern already exists in the same class (SaveStoredCore, 1204-1230). Settings same hole (MainWindow.xaml.cs:176; ClipSharedSettings.cs:141-147) — truncated settings silently load as defaults, emptying `Privacy.ExcludedApps`.
3. **Read-modify-write races across three writers** (high/medium) — capture (threadpool), OCR worker (OcrQueue.cs:88), UI actions (dispatcher) each do GetItems→Save as separate lock acquisitions (662-691, 1006-1018, 1109-1137). Concrete: OCR completing after a new copy overwrites the store with a pre-copy snapshot — the copy vanishes. Fix: one semaphore around each mutator's full read+mutate+save.
4. **Updater kills all WebView2 machine-wide** (med/small) — ClipUpdateService.cs:121 `Stop-Process -Force` unfiltered; scope by command-line user-data-folder or parent PID. Also: if all copy retries fail, Clip is left partially overwritten and never restarted (124-133).
5. **Capture split-brain: Watcher registered at startup while Shell declares itself sole owner** (med/medium) — App.xaml.cs:202-204 comment vs StartupRegistration.cs:104-113; two processes can both capture and write history.json with only in-process locks. Have watcher skip capture when the shell mutex exists (IsRichPaletteRunning already checks it, Watcher/Program.cs:567).
6. **Mouse hook can be silently dropped by Windows** (low/small) — LowLevelHooksTimeout uninstalls stalled hooks; fallback timer only starts if install failed (1805-1810). Keep the 50ms poll running alongside.
7. **Shell capture retries all exceptions with Thread.Sleep on the UI thread** (low/small) — up to ~270ms frozen (2391-2408); Watcher already filters transient failures correctly (Program.cs:1845-1846) — port it.

## Performance

1. **Row image/video thumbnails decode synchronously on the UI thread inside palette-open** (high/medium) — IconFor → LoadCachedBitmap / IShellItemImageFactory.GetImage (MainWindow.xaml.cs:3699, 9490, 9538; SourceAppIcons.cs:285); cold video thumbnails can cost hundreds of ms before first frame. The async swap-in pattern already exists twice (FaviconCache at 3638-3654; SourceAppIcons STA resolver at 118-145) — paint glyph, swap thumbnail.
2. **Cache eviction wipes entire caches** (med/small) — RememberRaster does `cache.Clear()` when full (9788-9791; preview cap 12, row-icon cap 256), destroying the neighbour prefetch every ~12 arrow steps. LRU-drop-oldest exists in SourceAppIcons (29-30) — copy it.
3. **Every arrow key re-runs the full O(n) filter + possible sync shell icon resolve** (med/small) — SelectItem → PrefetchNeighbouringImages → FilteredItems() (4134, 4465); reuse the list RenderItems already computed; TryGetCached before Resolve (9563).
4. **Rows never reclaimed after deep scroll** (med/small) — StackPanel only appends (3381-3479); with Unlimited history a bottom-scroll's visual tree lives while concealed. Mark dirty on conceal past a screenful (`_itemsDirtySinceRender` exists).
5. **80k-char text assigned into a wrapping TextBox synchronously** (low/small) — 687, 4205-4212; measure with OpenBenchHarness first, then chunk-render.
6. **~20-25MB of 900px previews pinned while hidden** (low/small) — static PreviewImageCache + ImagePreview.Source (685, 714, 4434); clear on the same 3-min idle horizon the WebView2 teardown uses (4170-4175).

Auditor's overall note: the open path is in unusually good shape (recent-first paint, deferred batches, cloak-until-first-frame, three purpose-built harnesses) — the remaining cost is synchronous image work.
